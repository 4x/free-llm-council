Synthesis-only Markdown: no more lonely subfolder

When synthesis.md is the only Markdown artifact requested, llm-council now writes one file directly under council-output/ — same slug + timestamp naming, with a -synthesis- marker and .md extension. Everything else still uses a per-run folder.

BEFORE Folder for one file

council-output/ question-20261014T1516/ synthesis.md ← folder exists only to hold this

One directory per run, even when it contained a single synthesis.md. Noisy listings, extra clicks, awkward globs.

AFTER Single file, same naming

council-output/ question-synthesis-20261014T1516.md ← directly usable

Format: <slug>-synthesis-<YYYYMMDDThhmm>.md, e.g. some-good-question-here-is-synthesis-20261014T1451.md. Collisions get -2, -3 suffixes.

Decision flow — save_markdown_artifacts()

1 · Collect_expected_markdown_files() → {prompt.md?, initial-*.md?, synthesis.md?}
→
2 · Test_is_synthesis_only() — is the set exactly {"synthesis.md"}?
→
3a · YES → file_save_single_synthesis_file(): temp file + atomic rename under markdown_dir
→
3b · NO → folderstaging dir + atomic rename to <slug>-<stamp>/
Content is identical — the single file holds exactly what synthesis.md held (header, requested/actual model, synthesis text). Only the path changes, so markdown_path may now be a file (is_file()) or a folder (is_dir()).
