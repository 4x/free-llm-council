llm-council · project overview

Ask every free model. Let a judge decide.

llm-council queries every currently free OpenRouter text model in parallel, then has a judge LLM critically synthesize all successful answers. Python API + CLI · DuckDB + Markdown storage · configurable judges · no model IDs hard-coded. Requires Python 3.11+ and an OPENROUTER_API_KEY.

uv sync
cp .env.example .env   # set OPENROUTER_API_KEY
uv run llm-council -q "Explain entropy" --save-synthesis markdown

1 · How a run flows (click a stage)

→ → →

Discover — free means provably free

Paginated /models with input/output_modalities=text plus max_price=0. Local validation: zero prompt + completion/output prices, zero request/reasoning/cache charges, no conditional overrides, text confirmed both directions. Routers, non-text, and EXCLUDED_MODELS skipped. Paid-judge scope re-queries without price caps.

Members — one request per free model

Bounded concurrency (MAX_CONCURRENCY=3) with REQUEST_INTERVAL=3.1s spacing (<20 starts/min). Retries honor Retry-After on 429/503 and in-flight-budget 402s; other 402s fail fast. Member failures warn but never abort — synthesis needs just one valid non-empty answer. Empty/truncated answers excluded.

Judge — validated before members run

Judge identity is validated before any member request. The judge gets the original question + all successful answers in full (never truncated). If the judge already failed as a member, or fails synthesis, the run falls back to successful council models. Compare result.judge vs result.judge_requested.

Store — opt-in, two sinks

DuckDB keeps the queryable record (questions + responses); Markdown keeps the readable record (folder per run, or a single <slug>-synthesis-<stamp>.md file when synthesis is the only artifact). Writes are incremental — initial answers survive a failed synthesis. No Markdown at all if synthesis itself fails.

2 · Judge strategies




ValueWhat it picksCost note


random (default)Random eligible modelFree scope


round-robinRotates sorted IDs, thread-safe in-processFree scope


free-routerID from FREE_ROUTER_MODELFree


autoID from AUTO_ROUTER_MODELPaid possible — needs judge_scope=all


most-intelligentTop of OpenRouter intelligence rankingBenchmark heuristic, not a guarantee


largest-contextBiggest context window — best for huge councilsNot an intelligence ranking


Exact model IDFixed, reproduciblePaid IDs need scope all




System prompt is external: prompts/judge.md via JUDGE_PROMPT; blank/unset falls back to the built-in JUDGE_SYSTEM. Candidates are treated as untrusted data.











3 · Python API


from llm_council import query, query_result

text = query("Explain entropy",
             save_synthesis="markdown")

r = query_result("Explain the Riemann hypothesis",
    judge="largest-context",
    save_prompt="both",
    save_initial_answers="both",
    save_synthesis="both")
print(r.synthesis, r.judge, r.markdown_path)
for f in r.failures:
    print(f.requested_model, f.error)


query() → str. query_result() → CouncilResult (prompt, answers, synthesis, judge + requested, usage, question_id, markdown path). Per-call overrides, Path inputs, literal_prompt, follow-ups via previous_synthesis/prior_turns. Errors raise CouncilError subtypes.






4 · CLI


uv run llm-council -q "Explain entropy" --save-synthesis markdown
uv run llm-council --file prompt.md -q "focus on proofs"
uv run llm-council --followup "more detail on caveat 2" --copy
uv run llm-council --export-markdown
uv run llm-council -q "..." --judge largest-context \
  --save-prompt both --save-initial-answers both \
  --save-synthesis both


Stdout renders synthesis as Rich Markdown; logs/errors go to stderr (exit 1; usage errors exit 2). --no-save kills all persistence. Follow-ups replay cached turns from .llm-council/ so roles strictly alternate.

Save modes per category: none/no/neither, duckdb, markdown, both. Slugs use first 6 meaningful words + UTC minute stamp (-2 on collision). --export-markdown backfills idempotently. Never run concurrent writer processes on one DuckDB file.

7 · Reliability & cost guardrails




RiskHandling


Flaky providersBounded retries, Retry-After honored, slow waits fail fast


Judge outageFallback to successful members; never retry known-failed endpoints


Paid surpriseMembers always free; auto/scope-all explicitly opt-in, no spend cap — watch usage


Leaky errorsAPI key redacted; provider errors may echo prompts — treat stderr as sensitive


--no-save confusionStops storage, not transmission — prompt still goes to providers




Troubleshooting: 402 vs 429, harness-only 403 (EXCLUDED_MODELS), judge fallback logs, and missing-Markdown causes are documented in docs/operations/troubleshooting.md.
